1. In order to serve multiple languages there would be a few options. We could load multiple Marian models and swap between them using a dict where the key is the language pair and the value is the model selected. This has a major limitation of memory usage, having too many could mean we use GBs of memory and then if we had multiple workers this would not be efficient so it would only work for if we were serving a couple of options. 
Secondly, we could swap the model to a larger, multilingual model that can automatically handle the languages for us. But this would likely require a change in architecture as it would be too big to store in the memory of each worker so could move towards one model with batching or implementing a queue system.

2. I have implemented unit tests but these would not be useful for continuous monitoring. In order to evaluate the model in production we could use something like BLEU score or METEOR for testing the quality of the translations as a first step. The best method would likely require human interaction. Currently this is stateless but in a production version we could store the requests and responses in a database, these could then be checked periodically by humans or we could ask users for feedback on their translations which would all go into the database. Then we would monitor to ensure that we stay above a certain rate of success.

3. I have tried to design this system in a way that multiple concurrent calls. We can use Gunicorn which spins up multiple uvicorn workers where each has it's own copy of the model so can handle requests in parallel. Uvicorn also helps with this as it can handle multiple concurrent HTTP requests and queue them effectively on each worker.
As I mentioned in my plan we could also scale horizontally by deploying the app in containers which could be orchestrated by something like Kubernetes and scale based on load.
If we ended up serving to many many users we could also consider adding an extra layer in the middle of the current two which could manage batching, where we translate multiple pieces of text in one go (this is supported by the Marian model).
